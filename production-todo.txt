=== 1. SECURITY (Critical) ===

[  ] 1.1  .env.local is NOT in .gitignore — raw Supabase keys and Google
          Maps API key are committed. Add .env.local to .gitignore and
          rotate every exposed key immediately.

[  ] 1.2  Anyone can register as "admin" — registration page lets users
          choose any role including admin. Remove "admin" from the
          client-side role selector; admin accounts should only be
          created via a backend/seed script or Supabase dashboard.

[  ] 1.3  Middleware does NOT enforce role-based route protection.
          /admin/* is accessible to any logged-in user (user or driver).
          Add role checks in middleware.js or in each admin page's
          server-side logic to redirect non-admin users.

[  ] 1.4  Supabase RLS policies for bookings are too permissive — any
          driver can UPDATE any pending booking's fields (not just
          status/driver_id). Tighten the "Drivers can accept pending
          bookings" policy to restrict which columns can be changed.

[  ] 1.5  No CSRF protection on forms (email/password login, register,
          booking creation). Supabase handles auth tokens but custom
          actions should be validated server-side.

[  ] 1.6  No rate limiting on auth endpoints — brute-force attacks on
          login are not throttled. Add rate limiting via Supabase's
          built-in config or a middleware solution.

[  ] 1.7  Google Maps API key is unrestricted — restrict it to your
          domain and APIs (Maps JavaScript API, Directions API) in the
          Google Cloud Console to prevent abuse and billing overruns.

[  ] 1.8  The TrackingMap.js has a suspicious key hack:
          `rawKey.startsWith('YAIza') ? rawKey.slice(1) : rawKey`
          This suggests the key was stored with a leading 'Y' prefix.
          Clean this up — use the correct key directly.

[  ] 1.9  No input sanitisation on pickup_address, cancel_reason, or
          hospital name/address fields. Add server-side validation
          and sanitise user input to prevent XSS/injection.

[  ] 1.10 Delete/hospital operations have no confirmation guards on the
          backend — RLS allows admin delete but there's no soft-delete
          check to prevent deleting a hospital with active bookings.


=== 2. AUTHENTICATION & AUTHORIZATION ===

[  ] 2.1  No email verification flow — users can sign up and immediately
          access the app without confirming their email. Enable Supabase
          email confirmation and add a "verify your email" interstitial.

[  ] 2.2  No "Forgot Password" / password reset flow. Add a reset
          password page and link it from the login form.

[  ] 2.3  Session enforcer (sessionEnforcer.js) relies on localStorage
          which is browser-only — will crash if accidentally imported
          server-side. Add a typeof window check or restructure.

[  ] 2.4  The sessionKicked state in useSession is set but never shown
          to the user — they get silently signed out. Show a modal or
          redirect to a "kicked from session" page explaining why.

[  ] 2.5  No token refresh handling — if Supabase JWT expires while the
          user is on an active trip, they lose tracking. Handle
          SIGNED_OUT / TOKEN_REFRESHED events gracefully.

[  ] 2.6  Driver registration creates a driver record client-side after
          signup. If the insert fails (line 66-74 in register/page.js),
          the user ends up with a driver role but no driver record.
          Move this to a database trigger or server action.

=== 4. DATA & DATABASE ===

[  ] 4.1  Hospitals are hardcoded in constants.js AND in the database.
          The book page falls back to constants if DB returns empty.
          This creates data inconsistency. Use DB as single source of
          truth and remove the hardcoded HOSPITALS array.

[  ] 4.2  No pagination on any data query — admin bookings limit(50),
          user bookings fetch ALL records. This will break at scale.
          Add cursor-based or offset pagination everywhere.

[  ] 4.3  Driver's is_busy flag is not reset when a trip is completed.
          updateTripStatus() doesn't toggle is_busy = false on
          COMPLETED status. This leaves drivers stuck as "busy".

[  ] 4.4  No database backup strategy documented or automated.

[  ] 4.5  location_logs will grow unbounded — no TTL, archival, or
          cleanup strategy. At 5-second intervals per active booking,
          this table will grow very fast.

[  ] 4.6  No indexes on location_logs(recorded_at) — queries to
          retrieve historical trip paths will be slow.

[  ] 4.7  No unique constraint preventing a driver from accepting
          multiple bookings simultaneously (only client-side guard
          via is_busy check, which is raceable).

[  ] 4.8  The seed.sql uses ON CONFLICT DO NOTHING but hospitals table
          has no unique constraint on name — duplicates can be inserted.

[  ] 4.9  No created_at index on bookings — admin dashboard sorts by
          created_at DESC but there's no compound index for this.

[  ] 4.10 No data migration for schema changes — only one migration
          file (001_schema.sql). Any future schema change needs a
          proper migration strategy.


=== 5. REALTIME & LOCATION ===

[  ] 5.1  Location broadcast creates a new channel on every component
          remount — channel names include Date.now() which prevents
          reuse. This can leak channels if not cleaned up.

[  ] 5.2  No fallback when GPS is unavailable or inaccurate — on
          desktop browsers or in poor signal areas, the app just shows
          an error. Add manual address entry or map-click-to-locate.

[  ] 5.3  useDriverLocation has currentLocation in its useEffect deps
          array — this causes the effect to re-run on every location
          update, creating infinite re-renders and re-subscriptions.
          This is a bug that will drain battery and CPU.

[  ] 5.4  No location accuracy indicator — users don't know if the
          GPS fix is 5m or 500m accuracy.

[  ] 5.5  Location broadcasting continues even when app is in background
          on mobile (or doesn't, depending on browser). Need to handle
          visibility change events and wake locks for reliable tracking.

[  ] 5.6  No geofencing — the app doesn't detect when the ambulance
          arrives within X meters of the pickup or hospital to auto-
          advance the trip status.

[  ] 5.7  Realtime subscription channel names aren't consistent —
          some use Date.now() suffix, others don't. Standardise.

=== 7. PERFORMANCE & OPTIMIZATION ===

[  ] 7.1  Every page with Navbar triggers a full auth state fetch

          the user profile from Supabase. Add a context provider or
          cache layer.

[  ] 7.2  Admin dashboard creates a new supabase client on every render
          via getSupabaseBrowserClient() called at component top level.
          Move to useMemo or a shared context.

[  ] 7.3  Admin dashboard polls every 30 seconds via setInterval even
          when the tab is not visible. Use document.visibilityState
          to pause polling when hidden.

[  ] 7.4  No image optimization — landing page components don't use
          next/image. Use Next.js Image component for automatic
          optimization.

[  ] 7.5  No code splitting strategy — all admin/driver/user pages

          pages that don't need interactivity (history, static lists).

[  ] 7.6  Google Maps loads the full SDK on pages that may not need it.
          Lazy-load the map component.

[  ] 7.7  No service worker for offline capability — critical for an
          emergency app where network may be spotty.

=== 12. CODE QUALITY & BUGS ===

[  ] 12.1 useDriverLocation.js — currentLocation in the useEffect
          dependency array causes infinite re-renders. Use a ref
          instead.

[  ] 12.2 Driver page — broadcastRef in the cleanup function captures
          a stale closure. The useEffect dependency array includes
          [driverData, supabase] but broadcastRef is read from state
          outside the effect.

[  ] 12.3 Admin dashboard — fetchDashboard is defined inside useEffect
          but supabase is in the dep array. supabase is recreated on
          every render from getSupabaseBrowserClient(), causing the
          effect to re-run infinitely. Same issue in multiple files.

[  ] 12.4 Admin bookings page — fetchBookings is not wrapped in

          isn't in the dependency arrays. ESLint would flag this.

[  ] 12.5 Navbar calls getSupabaseBrowserClient() at the component
          body level (not in a hook or effect), creating a new client
          reference on every render.

[  ] 12.6 No TypeScript — the entire app is plain JS with no type
          safety. Consider migrating to TypeScript for production.

[  ] 12.7 No consistent error handling pattern — some hooks swallow
          errors, others set state, others console.error. Standardise.
